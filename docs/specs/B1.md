# B1 · Voice profile

**Status:** Approved 13 Oct 2026. Built; PostHog events, help note and the real-user tone check (Arman) still to do before "Accepted".

Build notes: the analysis runs inside the A4 import step, so the profile is ready when the page opens. The 5-a-day limit counts logged `voice_analysis` calls in the last 24 hours.

## User story
As a user who imported my posts, I see what Qiva Reach learned about how I write, and I can fix any part of it, so every draft sounds like me.

## Acceptance criteria (locked)
Stores tone, average length, emoji use, banned and signature phrases; user can view and edit each field.

## How the profile is made
| Field | How it is filled | Editable as |
|---|---|---|
| Average length | Counted from imported posts (mean words per post, rounded to 10) | Number, 20–400 words |
| Emoji use | Counted from imported posts: none (0 emoji in 80% of posts), frequent (3+ emoji in 40%+ of posts), otherwise light | None / Light / Frequent |
| Tone | One fast-model call reads up to 20 posts and writes a short description, for example "direct, warm, short sentences, asks questions" | Text, max 200 characters |
| Signature phrases | Same call suggests up to 5 phrases or sentence openers the user actually repeats | Chips, add and remove, max 10 |
| Banned phrases | Starts from a default list of AI clichés (for example "game-changer", "unlock", "delve", "in today's fast-paced world", "thrilled to announce"); user can add and remove | Chips, max 30 |

The two counted fields work without AI. If the AI call fails, those fill in and Tone is left empty with: "We couldn't read your tone. Write it yourself or try again."

## Data
- Table `voice_profiles` already exists. Migration adds `analyzed_at timestamptz` and `tone_source text` (`ai` or `user`) so we know if a human edited it.
- Every AI call logged in `ai_usage` (feature `voice_analysis`, model, tokens, cost). Model from env `ANTHROPIC_MODEL_FAST`.
- Prompt in `src/ai/prompts/voice-analysis.v1.ts`. Posts longer than 1,500 characters are cut for the call.
- Row-level security: only members of the workspace read or edit; editors and owners write.

## Privacy and compliance
- Post text goes to the Anthropic API for this one analysis. The privacy policy must say this before launch (Arman, with the legal pages). The screen says: "We use an AI model to read your posts. Your posts are never shown to other users."
- Passes the LinkedIn gate: the user's own pasted text only; nothing is read from LinkedIn.

## Behaviour rules
- Time to first result: under 15 seconds.
- Re-analysis is limited to 5 a day per user, with a clear message.
- PostHog events: `voice_profile_viewed`, `voice_profile_saved` (fields changed, no content), `voice_reanalyzed`.

## Acceptance tests
1. Unit: average length and emoji classification on sample post sets, including no emoji, one emoji, many emoji.
2. Unit: banned-phrase defaults load; add, remove and the 30 limit work; duplicates ignored.
3. AI call tested with a stored sample response (no network in CI); malformed or empty reply gives the "couldn't read your tone" path and keeps the counted fields.
4. Playwright: import 5 posts, land on /app/voice, edit every field, reload, values persist.
5. Playwright: "Learn again" asks first; banned phrases survive it.
6. RLS: another user cannot read or change this profile.
7. One manual check with a real call on 3 real users' posts: tone reads as true to them (Arman collects).
8. 390 px phone, keyboard only, visible focus.
